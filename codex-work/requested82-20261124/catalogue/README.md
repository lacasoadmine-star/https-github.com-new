# Active82 source registry and working-release dashboard gate

The exact82 labels remain in the user's order. Existing reserved continuation identities are retained where the same title was already in progress. Similar labels stay separate; no name is silently redirected to an older financial game. Dated official-page metadata is retained only as metadata. Unverified spellings such as `Gates of Meryln` and `Samba Da Deusa` receive no invented provider alias.

The user's current dashboard directive is enforced: **only working, reviewed releases can become dashboard cards**. Full82 registration is source progress only. The served browser catalogue contains exclusively qualified releases. With no qualifying release, the wrapper returns the previous root Response unchanged, without a loader, section, placeholders or new cards. All old game, wallet, authentication, payment and portal routes delegate unchanged. Existing named exports are retained through the additive entry module.

The qualification gate requires the game's own implementation, seven current official-reference rounds, own asset and backend module hashes, financial integration, controls/audio/artwork, Playwright, existing-backend connection and actual live gameplay evidence at the matching source commit. A card, component test, visual preview, installed host or manually flipped release switch cannot meet that gate by itself. The current registry has **zero qualified games**; no new game or production deployment is claimed by this source.

`buildDeployment({activeMainModule,sourceCommit,releaseDescriptors})` emits five additive modules and pinned source/build metadata. It neither activates a Worker nor changes any account, ledger or database. Supply only the actual reviewed live-game descriptors, never the synthetic descriptors from the tests. Do not deploy an empty catalogue as progress on a finished game.
