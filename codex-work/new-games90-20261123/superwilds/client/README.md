# Super Wilds client continuation

`main.mjs` exports `mountSuperWilds({root,transport,subject,journalStorage,keyFactory,audioFactory,onError})`. Load `style.css` and supply the existing authenticated host transport. The mount imports the new same-game renderer and observed rules. Every accepted outcome and wallet amount comes from the server. Missing or disabled host integration never creates a fake balance or a local outcome.

The controller prepares and journals the original action **before** dispatch. The owner-scoped session journal contains only its request key and semantic payload, including the pinned host authority; no wallet or outcome is persisted. Lost replies and real reloads use `recover(originalPreparedAction)`. Repeated SPIN while waiting or animating requests only a local STOP. TAKE accepts one bound collection acknowledgement and remains available for an already accepted win after new wagers are disabled. X2 sends a server colour choice only when `canDouble` is explicitly true; the actual host currently keeps X2 disabled until its own approved model exists.

The mounted game includes aligned semantic controls, Space/Enter repeat guards, sound Yes/No startup, rules/payline/settings/history dialogs, focus containment, host bet choices, AUTO count and all three observed win/balance limits. AUTO starts from the current accepted balance and stops on limits, visibility, offline, pagehide, blur or disposal. Persisted pageshow and online events reconnect without discarding an uncertain original action. Procedural Web Audio is original sound design; it is not an assertion of provider sample or audible parity.

The focused `controller.test.mjs` checks original-key retries, reload recovery, one debit/collection intent, invalid receipts, journal failure, model retirement collection, immutable views, session binding, AUTO baseline/limits and reconnect. `browser-qa.mjs` is a plain Node executable using `ZPLAY_QA_NODE_MODULES` for Playwright and `ZPLAY_SUPERWILDS_QA_OUTPUT` for reports and screenshots. Its isolated HTTP fixture uses synthetic authoritative receipts and disposable in-memory accounting; it cannot reach or mutate production. It covers four viewport sizes, ten distinct controlled round views per viewport, exact hitboxes, STOP, TAKE, keyboard repeat, AUTO limits, settings/audio nodes and actual reload recovery. Source hashes are recorded in its report. The current local environment cannot launch Chromium because socket creation is denied; passing browser proof must come from the isolated CI runner. No live financial verification is claimed by this source.
