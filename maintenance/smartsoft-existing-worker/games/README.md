# Existing Superwin game repairs

These changes run on the existing `superwin-player` Cloudflare Worker and its existing Railway account backend. They do not create a reference website, replacement wallet or separate player.

## Actual release

Cloudflare version `d34ea3b7-7f0f-443c-a53d-89bb41d1fdea`, deployment `38642714-d969-4662-aaa7-db253caaae31`. Nine existing native backend models were already enabled, but the old Worker catalogue marked all nineteen candidates unpublished and rejected state/action requests before the signed backend. The reviewed catalogue changes only those nine IDs and exact deployed versions. All other original modules and the existing wallet namespace remain intact.

Multi Hot 10 has a dedicated state-driven game at its existing `/independent74/fresh74.html` route. Its genuine textures/audio are drawn from a fresh official demo; client code, animation timing, controls and rendering are independently implemented. The game uses the existing strict account and receipt API. Its probability model is independent and disclosed in Rules; this does not reproduce SmartSoft proprietary server math.

The nine retained native operator models likewise use their declared independent ZPLAY math, as reported by their deployed versioned configurations. Fixing the Worker allowlist reconnects those existing implemented models; it is not a claim that every official animation, bonus or probability model is identical.

Six native motion-module URL overrides cover nine game layouts. STOP pauses decorative movement while waiting for a valid server receipt, and the receipt still controls the final grid. No financial outcome or account balance is generated by the renderer. MultiHot5 and FoxyHot20 accepted routes are preserved.

## Resource delivery

`native-game-resources.mjs` adds a separate SQLite Durable Object class to the same Worker. It serves only actual allowlisted game code, textures and sound. All uploads use authenticated Cloudflare SQL requests generated by `prepare_native_resource_upload.py`; there is no public upload or reference-viewer route. Existing assets and the LocalDemoWallet namespace are retained. Upload requests and raw research resources are private build artifacts and must not be committed.

`native-game-entry.mjs` retains existing public game/module URLs. Its imports name the reviewed deployed modules; deployment must preserve the rest of the existing module package and asset binding. The catalogue patch metadata records the exact before/after SHA256. Verify those hashes against the current Worker before replacing the one original catalogue module.

## Account availability

`reference-finance-addon.mjs` and `capacity-source-patches.json` filter private fresh-state stakes using the already locked house row. The server still rechecks reserve before RNG. `shared/fresh74-account.mjs` clears pending actions only for a definite no-charge reserve rejection; network errors and uncertain responses keep their original retry token. The backend build script preserves all three original inner math module bytes and never changes historical records.

## Verification and limits

Run the focused Node tests under `tests/`: catalogue signed forwarding/auth/origin/session/version checks, account reserve filtering and uncertain-action retry, persisted binary resource delivery, and native STOP clocks. `multihot10/verify_live.py` tests the deployed UI with isolated financial API fixtures, including one submission, gamble/history/bet, bounded autoplay, same-token recovery and seven phone/desktop viewports. Browser fixtures never create a real account, wager or database write.

Fresh official demo native-play evidence and private live-vs-demo screenshots live outside source control. Collection covers the official catalogue of 74 titles, but evidence completeness and new game reconstruction remain in progress. Do not describe all74 as built or claim authenticated real-money end-to-end verification.
